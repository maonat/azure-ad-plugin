When enabled, Jenkins reads the roles claim from the Entra ID JWT token instead of querying the Microsoft Graph API for group memberships.

How it works:

Each app role (e.g. jenkins-admin, jenkins-deployer) is mapped to a Jenkins group authority. You can then use these role names in the permission matrix at global, folder, job, and node level to control who can access what.

Setup required in Azure:

  1. In your App Registration → Manifest, define app roles in the appRoles array (e.g. "value": "jenkins-admin")
  2. In Enterprise Applications → your app → Users and Groups, assign users or groups to the defined app roles

Benefits:

  • No GroupMember.Read.All or User.ReadBasic.All permissions needed
  • Compatible with federated credentials / workload identity (no client secret)
  • Map Azure app roles to specific Jenkins jobs/folders for granular access control

Limitations:

  • User/group autocomplete in the permission matrix is not available — type role names (e.g. jenkins-deployer) directly as GROUP entries
  • REST API / programmatic auth requires the user to have logged in interactively first
